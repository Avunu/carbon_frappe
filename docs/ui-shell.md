# UI Shell header

The header is Carbon's UI Shell, class for class — `cds--header`, `HeaderMenuButton`, `HeaderName`, `HeaderNavigation` + `HeaderMenu`, `HeaderGlobalBar`, `HeaderPanel` + `Switcher` — mounted as light DOM by `js/anatomy/ui_shell.ts` and styled by `@carbon/styles`' own header, header-panel and switcher mixins. It runs Carbon's **g100** theme in both desk themes through a zone class (`cf-zone-g100`) that shares the dark theme's token emission.

Everything it shows is a projection of frappe v16.50's **module sidebar** (`frappe.app.sidebar`), which is what resolves a route to a shell (a key of `frappe.boot.module_sidebars`), names the app that owns it and renders its items. The dock beside it is frappe's module switcher inside an app, and the left panel is frappe's too; the header takes nothing off either.

- **Header name** — `<app title> <module label>`, e.g. "ERPNext Projects" at `/desk/projects`, from `sidebar.get_sidebar_app()` and the shell's `label`; no prefix for a shell no app owns. On the launcher — the page that hides both the sidebar and the dock, which is `/desk` — it reads "Desktop". It links to the module's landing route (`sidebar.module_landing_route`, the route the dock's tile for that module opens).
- **Header links and sub-menus** — the sidebar's top-level rows: a `Link` is a header link, a Section Break with children is a sub-menu. They are read from the sidebar's rendered DOM rather than from `boot.module_sidebars`, so frappe's own routing (`get_route()`, six branches, plus the shell prefix written into every desk href) and render decisions are inherited, never re-derived. `aria-current` is the one row frappe lights (`.active-sidebar`, written by `find_active_item()`), never a second rule. Carbon's header has no overflow behaviour, and a module sidebar carries anywhere from one to eighteen top-level rows (ERPNext's Stock has 13), so the bar is measured and the tail folds into a **More ▾** sub-menu; below Carbon's `lg` breakpoint (66rem) the nav hides and the sidebar carries every link, as Carbon's guidance says it should.
- **Utilities** — search, the notifications bell and the account menu, three `cds--header__action` cells the theme builds once. Each calls what frappe's own control calls, so frappe keeps the behaviour: **search** carries `.navbar-modal-search-mobile`, the class the awesome bar delegates its click to; the **bell** calls `frappe.ui.sidebar_panels.toggle("notifications")` and keeps the row's `.sidebar-notification` class, so frappe mirrors the panel's state into `aria-expanded` and does not count a click on it as "outside"; the **account** cell is `sidebar.create_user_menu`, the menu the sidebar chip and the dock avatar share. The unread badge is frappe's `.notification-count`, which it writes into wherever it is. The notifications panel is frappe's `frappe.ui.SidebarPanel` with its own content and dismissal rules; the theme re-hosts its element on `<body>` (the sidebar's container is hidden on the launcher) and draws it as a right header panel, g100, 360px, under the header. Opening the bell closes the switcher and the assistant, and any of them closing the bell is frappe's outside-click rule. frappe's own copies of these controls — the Search and Notification rows, the sidebar's user chip, the pinned dock's avatar and the launcher's own navbar — stay in the DOM and are not drawn while the header is mounted; apps that add rows to the launcher's avatar menu (`desktop_page.add_menu_item`) therefore have no route to them from the header.
- **Switcher** — the far-right action opens a right panel that mirrors what the `/desk` desktop lays out. On the default **Apps** screen that is `boot.app_data` filtered to the apps that opted in (`on_apps_screen`), ordered by `sequence_id`, each leading where its tile does (`sidebar.app_landing_route`); the app that owns the shell on screen is selected. Modules are not in it, because the dock is the module switcher. On a site still set to the retiring **Desktop Icons** page it is the icon grid instead — `boot.desktop_icons` with the grid's own rules re-applied (hidden icons dropped, orphans promoted, `idx` then label order, a Folder or an App with workspaces under it as an expandable row) — and the icon that opens the shell on screen is selected. The Desktop launcher sits below a divider in both.
- **Hamburger** — delegates to frappe's sidebar toggle and mirrors `sidebar.sidebar_expanded` in `aria-expanded`. Beside a pinned dock a collapsed sidebar slides shut instead of folding to a rail, and the control that brings it back stays enabled. It keeps the Menu glyph: Carbon's ✕ means "an overlay is open", and frappe's sidebar collapses rather than going away. The page head's own hamburger (page.html) is hidden while the header is mounted, so there is one.

**Beside the dock and the sidebar.** The header is fixed at the top, so its 3rem row is reserved on the dock (while pinned), the sidebar and the content column, and each is cut to the viewport minus the header; a panel beside the sidebar is too (it overflowed by the header's row). The pinned dock starts under the header, which keeps its logo visible. A floating dock is centred on the room that is left, and the dock sits at z-index 1022 — above the sidebar and its overlay, under the assistant (1025) and the header (1030). The dock's tiles are squared and take the sidebar's hover, selection bar and focus ring. The module name appears in the header and in the sidebar's own header, which stays because its menu is the only home of Edit Sidebar, Help and, on an app with no dock, the Modules submenu.

The header re-renders after `Sidebar.prototype.make_sidebar` (the one place frappe rebuilds the sidebar DOM; `sidebar_setup` fires _before_ the state changes and is deliberately unused), re-marks the current link after `highlight_active_item` and re-reads the model after `apply_page_visibility` (where the launcher and the modules are told apart) and on every route change, rebuilding only when what it renders from changed. It never mounts where frappe fills `<header>` itself (read-only, impersonation, announcement widget, mobile), and everything above that hides frappe's own copies is gated on the header having mounted. The AI assistant lives on the header, so it is not available below the mobile breakpoint (`innerWidth < 768`): there is no trigger and no panel on a phone.
